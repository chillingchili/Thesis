# Automatic phone output improvement experiments

All variants replay the same 30 Coach C source clips once on the Xiaomi. This is development evaluation on already inspected clips, not a new independent test. Original GRU weights and 0.60 classification threshold are unchanged. All raw logs, APK hashes and exact feedback strings remain in the corresponding directories.

| Variant | Classified /30 | Confident /30 | Reference-category matches among confident | Corrective/positive output /30 | No completed output | Max detected-end to UI ms |
|---|---:|---:|---:|---:|---:|---:|
| CPU installed baseline | 6 | 4 | 1/4 | 2 | 1 | 397 |
| GPU only | 25 | 6 | 4/6 | 5 | 4 | 1165 |
| GPU + automatic quality candidate | 24 | 10 | 7/10 | 18 | 3 | 423 |

## What changed

- GPU pose acquisition increases available real observations. The classifier is unchanged.
- Motion is normalized to an 80 ms reference interval and smoothed with a 200 ms time constant, instead of measuring unnormalized displacement per frame. Tracking gaps over 500 ms reset this signal. This is a candidate automatic gate; no user recording button is added.
- Shared mechanics rules can provide corrective advice despite uncertain classification only after at least 32 real poses spanning 1500 ms. Only existing rules explicitly applicable to all three serve types qualify. No subtype-specific paddle advice or positive overall-form judgment is generated by this fallback. The text explicitly discloses uncertain serve classification.

The candidate emitted 11 corrective outputs while classification was uncertain. This increase is partly a feedback-policy change, not improved classification accuracy. CORRECTIVE/POSITIVE indicates output availability, not proven coaching validity. Reference categories are not independent Coach C subtype ground truth.

## Limits

The gate and feedback policy were changed together in the final candidate; their individual effects are not isolated. One replay per clip does not establish repeatability. GPU and CPU trials were sequential, not counterbalanced for temperature. No new clips or Coach C judgments were collected, and old ratings were not transferred to the new messages. Reuse for development limits claims about generalization.

Timing runs from automatic end detection to UI assignment. It excludes decoding/model initialization and is not an independently measured physical-serve-end-to-visible-feedback interval. Results before file end and absent results cannot be treated as proven two-second successes.

## Installed default

The improved GPU + automatic quality configuration is installed on the Xiaomi. Original GRU weights remain unchanged. The final build enables the tested settings by default, displays UNCERTAIN below 0.60, and falls back to CPU if GPU initialization fails. CPU fallback was not exercised on this GPU-capable phone. Final build/lint and 43 JVM tests passed. Final installation succeeded.

Corrective output availability increased from 2/30 to 18/30; 11 candidate outputs used shared mechanics rules while classification remained uncertain. This is partly a feedback-policy gain, not an equivalent gain in classification accuracy or independently validated advice quality. Three clips had no completed output; C005 arrived 3126 ms after source-file end. Thus consistent two-second delivery is not established. The final installed APK hash and tested APK hash are separately recorded in final_validation.json.
